3. PUBLICATION OUTCOME SAFETY

lib/productPublicationStatus.ts performs an authoritative, read-only product
lookup and classifies published, draft, archived or unknown. Missing rows,
malformed results, failed reads and thrown requests produce unknown. It does
not infer draft from an error, Stripe state, cached UI state or old revision.

/api/admin/products action publication-status is owner-gated before body access,
validates the product ID, and returns only current publication/revision/sync
fields with Cache-Control: no-store. It does not initialize Stripe or call an
RPC. No operation ID or write attempt is required to check status.

After the final publication RPC, both review-publish and legacy publish read
the current authoritative state even if the write response reports an error
or throws. A confirmed published row is reported published. A confirmed draft
or archived row is reported as that state. Unavailable status produces:
  Status unklar — bitte aktualisieren
The confirmation read intentionally does not insist on the attempted revision:
it reports the current state after a concurrent edit, archive or publication.
There is exactly one publication write attempt in this recovery path. No
automatic publication retry or compensating unpublish/save/archive occurs.
The installed PostgREST client retries idempotent read methods only, not RPC
POST writes; the existing SDK behavior and revision/idempotency guards remain.

The browser independently re-reads publication-status after success streams,
partial streams, non-200 responses, lost responses and network errors. It shows
Veröffentlicht when a lost response is resolved to published, Entwurf when the
read confirms draft, and the exact unknown text when it cannot establish state.
Normal completion appears only after the final result and a confirming read.
A success stream alone never overrides draft/unknown authoritative state.
For unknown results, the cached table row also shows unknown rather than its
old draft/published label. The publish button is disabled for that product.
Neu laden performs reads only and resolves the state without retrying a write.
The owner may explicitly publish again only after a known draft is established.
Existing deterministic Stripe identity/lookup keys and concurrency protections
remain in place; no Product or Price deletion/repricing was added.

Readback is a point-in-time observation, not a guarantee against a later
independent edit. Unknown outcomes are retained as unknown until a read succeeds.
There is no new migration and no Product Manager redesign or feature expansion.
